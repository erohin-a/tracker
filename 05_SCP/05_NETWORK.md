# Вкладка «Сеть» (SCP)
Статус: черновик
Дата: 2026-10-12
Связанные файлы KB: 05_SCP\02_CERTIFICATES.md, 06_DEPLOY\02_NGINX_TLS.md, 06_DEPLOY\03_WINDOWS_SETUP.md, 06_DEPLOY\06_INSTALLER.md

## Назначение
Вкладка SCP для настройки сетевого доступа к серверу Tracker:
просмотр адресов машины, LAN-доступ, правило брандмауэра, единый
конфиг деплоя `deploy.json`, вшиваемый адрес сервера для клиента.

## Что показывает и делает

### 1. Адреса этой машины
- **Hostname** — имя компьютера (например, `ws147`).
- **Список IPv4** — все сетевые интерфейсы, кроме loopback и APIPA.
- Кнопка **«Обновить адреса»** — пересканировать интерфейсы.

Основной LAN-IP определяется через временный UDP-сокет к `8.8.8.8`
(пакеты не отправляются), поэтому подхватывает адрес «активного»
интерфейса.

### 2. LAN-доступ
- **LAN-IP** — адрес, по которому сервер доступен из локалки.
- **Сертификат** — статус: входит ли LAN-IP в SAN текущего сертификата.
  - зелёный фон — OK, IP в SAN;
  - красный фон — IP не в SAN, клиенты с других ПК откажут с
    `CERTIFICATE_VERIFY_FAILED`. Решение: перевыпустить сертификат.
- **Кнопки брандмауэра**:
  - **«Разрешить в брандмауэре (443)»** — добавляет правило
    `Tracker HTTPS` (вход, TCP, порт 443, все профили), через UAC.
    Команда: `netsh advfirewall firewall add rule name=Tracker HTTPS dir=in action=allow protocol=TCP localport=443`.
  - **«Проверить правило»** — `netsh advfirewall firewall show rule`.
  - **«Удалить правило»** — закрывает доступ с других ПК.
- **«Открыть админку в браузере»** — открывает URL из `admin_url`
  (из `deploy.json`).
- **«Перевыпустить сертификат с LAN-IP»** — автоматический renew,
  собирает SAN как `localhost, 127.0.0.1, LAN-IP, hostname,
  alias, alias.local` и вызывает `certs.generate_self_signed`.
  Подробнее — в `02_CERTIFICATES.md`.

### 3. Адрес для клиента (deploy.json)
Три поля, которые читаются/пишутся в `D:\tracker\deploy.json`:
- `server_url` — URL, вшиваемый в установщик (например
  `https://192.168.0.35`).
- `admin_url` — URL админки (обычно `server_url + /admin/login`).
- `hostname_alias` — короткое имя (например, `tracker`).

Кнопки:
- **«Сохранить в deploy.json»** — записать значения в файл.
- **«Подставить LAN-IP»** — заполнить `server_url`/`admin_url`
  текущим LAN-IP.
- **«Перечитать deploy.json»** — загрузить значения заново.

### 4. hosts-строка (полуавтомат)
Строка вида `<LAN-IP>` TAB `tracker` — то, что нужно добавить в
`C:\Windows\System32\drivers\etc\hosts` на клиенте, чтобы
работал короткий адрес `https://tracker/`. Кнопка копирует строку
в буфер обмена.

## deploy.json — единый конфиг деплоя

Файл `D:\tracker\deploy.json`. Формат:

    {
      "server_url": "https://192.168.0.35",
      "admin_url": "https://192.168.0.35/admin/login",
      "cert_cn": "localhost",
      "cert_san": ["localhost", "127.0.0.1"],
      "cert_days": 365,
      "hostname_alias": "tracker",
      "last_lan_ip": "192.168.0.35"
    }

Читается/пишется через `control/deploy.py`:
- `load()` — прочитать (дополняет дефолтами).
- `save(data)` — записать.
- `set_values(**kw)` — обновить поля.
- `get(key, default)` — одно поле.
- `ensure_file()` — создать с дефолтами, если нет.

Используется:
- вкладкой «Сеть» — для показа и правки;
- `control/build.py` (`prepare_client_env`) — вшивает `server_url`
  в `client/.env`;
- (планируется) вкладкой «Сборка» — для показа, что уедет в установщик.

## Как это правильно работает

1. Узнал LAN-IP (вкладка «Сеть» показывает автоматически).
2. Убедился, что IP в SAN сертификата (иначе — кнопка renew).
3. Разрешил порт 443 в брандмауэре.
4. Вписал `server_url` в `deploy.json` (кнопка «Подставить LAN-IP»).
5. Собрал установщик — `server_url` уедет вместе с ним.
6. Раздал сотрудникам.

## Про короткое имя tracker

`https://tracker/` работает только если DNS знает про это имя. Три
варианта:
1. **hosts на клиентах** (полуавтомат) — SCP даёт строку для копирования.
2. **DNS на роутере** — если поддерживает dnsmasq/локальные записи.
   Один раз настроил — работает для всех устройств в сети.
3. **Игнорировать** — работать по IP `https://192.168.0.35`.

SCP сейчас поддерживает уровень 1 и частично 2 (готовит данные).

## Планы (не реализовано)
- Автогенерация записи в DNS через API роутера.
- Проверка доступности порта 443 извне (с другого ПК).
- Кнопка «Проверить соединение» — открывает HTTPS-запрос к серверу
  с параметром проверки сертификата.
- Работа с wildcard-сертификатами.
