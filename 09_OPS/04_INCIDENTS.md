# Инциденты
Статус: черновик
Дата: 2026-10-02
Связанные файлы KB: 09_OPS\01_RUNBOOK.md, 07_QUALITY\02_KNOWN_ISSUES.md, 09_OPS\02_MONITORING.md

## Назначение
Описать порядок работы с инцидентами в «Трекере»: классификация, действия по уровням, восстановление, пост-мортем. Это карта для администратора и дежурного, который столкнулся с проблемой.

## Содержание

### Что такое инцидент
- Событие, нарушающее нормальную работу системы.
- Отличается от «известной проблемы» (`07_QUALITY\02_KNOWN_ISSUES.md`) тем, что требует немедленной реакции.
- Примеры: сервер не отвечает, клиенты не синхронизируются, БД повреждена, отчёт не считается.

### Классификация по критичности

| Уровень | Название | Что происходит | Время реакции | Время восстановления |
|---|---|---|---|---|
| **P0** | Критический | Сервер полностью недоступен, данные под угрозой | Немедленно | < 1 часа |
| **P1** | Высокий | Ключевая функция не работает (регистрация, синхронизация) | < 30 минут | < 4 часов |
| **P2** | Средний | Отдельные функции деградировали (отчёты, экспорт) | < 4 часов | < 24 часов |
| **P3** | Низкий | Косметика, не блокирует работу | По плану | По плану |

### Примеры по уровням

#### P0 — Критические
- Сервер не отвечает (`curl` не возвращает ответ).
- Все контейнеры упали.
- БД повреждена, `pgdata` удалён.
- Данные массово потеряны.
- Компрометация секретов (утечка `SECRET_ENCRYPTION_KEY`).
- Диск заполнен на 100%, ничего не пишется.

#### P1 — Высокие
- Клиенты не могут зарегистрироваться (`401` на bootstrap-токене).
- Синхронизация не работает (клиенты копят, но не отправляют).
- Планировщик не запускает задачи (партиции не создаются).
- `close_stale_sessions` не работает → висящие сессии.
- Отчёты не считаются (`500`).
- nginx не проксирует (`502`, `504`).

#### P2 — Средние
- Экспорт CSV/XLSX работает с ошибками.
- PDF с крокозябрами.
- Pivot-таблица пустая.
- Календарь не сохраняется.
- Графики работы не применяются.
- Алерты не отправляются (если уже настроены).

#### P3 — Низкие
- Тёмная тема не покрывает часть элементов.
- Retranslate главного окна не работает.
- Косметические баги в UI.
- Отсутствие удобных кнопок.

### Порядок действий при инциденте

#### Шаг 1. Зафиксировать
- Что: сервер не отвечает, клиенты не синхронизируются, и т.д.
- Когда: время обнаружения.
- Где: сервер / клиент / сеть.
- Кто: пользователь / мониторинг / сам заметил.

#### Шаг 2. Классифицировать
- Определить уровень (P0/P1/P2/P3) по таблице.
- От этого зависит скорость реакции.

#### Шаг 3. Стабилизировать
- **P0:** немедленно восстановить работу. Приоритет — вернуть систему, не искать причину.
- **P1:** локализовать проблему, применить обходное решение.
- **P2/P3:** запланировать исправление.

#### Шаг 4. Собрать диагностику
```powershell
cd D:\tracker
docker compose logs api --tail=200 > _diag_api.log
docker compose logs nginx --tail=100 > _diag_nginx.log
docker compose logs db --tail=100 > _diag_db.log
docker compose ps > _diag_ps.log
docker compose exec -T db psql -U tracker -d tracker -c "\dt" > _diag_tables.log
curl.exe -k https://localhost/api/v1/version > _diag_version.log
Шаг 5. Найти причину
Проверить 07_QUALITY\02_KNOWN_ISSUES.md — возможно, известная проблема.

Проверить 09_OPS\01_RUNBOOK.md — типовые сбои.

Проверить логи на Error|Traceback|Exception.

Шаг 6. Применить решение
Из RUNBOOK или KNOWN_ISSUES.

Если нет — искать в коде, пробовать фикс.

Если не получается — эскалация к разработчику.

Шаг 7. Проверить восстановление
API отвечает.

Клиенты синхронизируются.

Планировщик работает.

Данные на месте.

Разобрать причину.

Предложить меры предотвращения.

Обновить документацию.

Типовые сценарии
1. Сервер не отвечает
Уровень	P0
Симптом	curl не возвращает ответ, клиенты офлайн
Действия	1. Проверить Docker Desktop. 2. docker compose ps. 3. Перезапустить контейнеры. 4. Если не помогает — down && up -d --build.
Профилактика	Автозапуск Docker Desktop, мониторинг.
2. БД повреждена
Уровень	P0
Симптом	db unhealthy, ошибки подключения
Действия	1. Не удалять volume. 2. Восстановить из последнего бэкапа. 3. Если бэкапа нет — данные потеряны.
Профилактика	Ежедневные бэкапы, проверка восстановления.
3. Клиенты не регистрируются
Уровень	P1
Симптом	401 на bootstrap-токене
Действия	1. Проверить /admin/tokens — есть ли активные. 2. Выпустить новые. 3. Проверить, что сервер доступен.
Профилактика	Мониторинг срока токенов, уведомление админа.
4. Синхронизация не работает
Уровень	P1
Симптом	Клиенты копят данные, но не отправляют
Действия	1. Проверить client.log. 2. getaddrinfo, SSL, 401. 3. Проверить API.
Профилактика	Мониторинг очереди, алерты.
5. Планировщик не работает
Уровень	P1
Симптом	Задачи не запускаются, партиции не создаются
Действия	1. SELECT * FROM scheduled_tasks. 2. Проверить логи API на scheduler. 3. Перезапустить API.
Профилактика	Мониторинг task_runs.
6. Отчёты не считаются
Уровень	P2
Симптом	500 на /admin/reports/generate
Действия	1. Логи API. 2. Известные проблемы. 3. Перезапустить API.
Профилактика	Тесты отчётов.
7. Диск заполнен
Уровень	P0
Симптом	Ошибки записи, БД не пишет
Действия	1. Очистить логи Docker. 2. Удалить старые партиции. 3. Удалить старые бэкапы. 4. Расширить диск.
Профилактика	Мониторинг свободного места.
8. Утечка секретов
Уровень	P0
Симптом	Подозрение на компрометацию
Действия	1. Немедленно ротировать секреты. 2. Проверить audit_log. 3. Перерегистрировать ПК при утечке SECRET_ENCRYPTION_KEY.
Профилактика	Хранение секретов, аудит.
