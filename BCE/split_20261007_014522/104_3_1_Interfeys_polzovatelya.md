### 3.1. Интерфейс пользователя

#### 3.1.1. Поля ввода данных о сотруднике

| Поле | Тип | Обязательность | Валидация | Описание |
|------|-----|---------------|-----------|----------|
| Фамилия | Текстовое | Да | 1–50 символов, только буквы, дефис | Вводится при первом запуске |
| Имя | Текстовое | Да | 1–50 символов, только буквы, дефис | Вводится при первом запуске |
| Отчество | Текстовое | Нет | 1–50 символов, только буквы, дефис | Вводится при первом запуске |

**Важно:** Все поля должны проходить валидацию на стороне клиента. При вводе недопустимых символов (цифры, спецсимволы) — показывать сообщение об ошибке. Данные сохраняются в `config.json` в директории пользователя.

#### 3.1.2. Кнопки управления работой

- **«Начало работы»** — запускает трекинг. Кнопка становится активной (зелёный фон), кнопка «Конец работы» — неактивной (серый фон).
- **«Конец работы»** — останавливает трекинг. Кнопка становится активной (зелёный фон), кнопка «Начало работы» — неактивной.
- **Взаимоисключение:** Одновременно активной может быть только одна кнопка. Состояние кнопок сохраняется при перезапуске приложения.
- **Защита от случайного нажатия:** При нажатии «Конец работы» — показать диалоговое окно подтверждения («Вы уверены, что хотите завершить рабочий день?»).

#### 3.1.3. Кнопка автозапуска

- **«Автозапуск»** — переключатель (toggle). Включённое состояние — клиент запускается при входе пользователя в систему.
- **Реализация:**
  - **Windows:** запись в реестр `HKEY_CURRENT_USER\Software\Microsoft\Windows\CurrentVersion\Run`.
  - **Linux:** создание `.desktop`-файла в `~/.config/autostart/`.
- **Визуальное отображение:** Текущее состояние отображается текстом («Включён» / «Выключен») и цветом (зелёный / серый).
- **Права:** Изменение автозапуска может требовать прав администратора (особенно на Windows). Предусмотреть обработку отказа в доступе.

#### 3.1.4. Индикатор статуса синхронизации

Блок «Последнее подключение к серверу» содержит:

| Элемент | Описание | Обновление |
|---------|----------|-----------|
| Дата и время последней успешной синхронизации | Формат: `ДД.ММ.ГГГГ ЧЧ:ММ` | При каждой успешной синхронизации |
| Количество несинхронизированных записей | Целое число | Каждые 30 секунд |
| Статус-индикатор | Зелёный — данные актуальны; жёлтый — есть несинхронизированные данные; красный — нет соединения | Каждые 30 секунд |
| Текстовое предупреждение | Если данные не передавались более 1 часа: «Данные не передавались с ДД.ММ.ГГГГ ЧЧ:ММ». Отображается красным цветом | Каждую минуту |

**Дополнительно:** Добавить индикатор состояния трекинга (активен / остановлен) в системном трее.

#### 3.1.5. Системный трей (рекомендуемое расширение)

- Клиентский модуль должен сворачиваться в системный трей при закрытии окна (а не завершать работу).
- Контекстное меню в трее:
  - «Открыть» — развернуть окно.
  - «Начать работу» / «Завершить работу» — быстрые действия.
  - «Отправить данные» — ручная синхронизация.
  - «Выход» — полное завершение приложения.
- **Реализация (PyQt6):** `QSystemTrayIcon` + `QMenu`.
- **Реализация (Tkinter):** библиотека `pystray` + `PIL`, запуск в отдельном потоке с `run_detached=True`.
