### 2.2. Технологический стек (уточнённый и обоснованный)

| Компонент | Технология | Обоснование |
|-----------|-----------|-------------|
| Язык | Python 3.11+ | Требование ТЗ; версия 3.11+ обеспечивает улучшенную производительность и поддержку асинхронности |
| Клиентский GUI | PyQt6 (рекомендуемый) или Tkinter | PyQt6 обеспечивает нативный вид, встроенную поддержку трея и потоков; Tkinter — минимальные зависимости |
| Серверный фреймворк | FastAPI + Uvicorn | Асинхронность, автоматическая документация OpenAPI, валидация Pydantic |
| ORM | SQLAlchemy 2.0 (async) | Поддержка асинхронных сессий, типобезопасность, миграции через Alembic |
| База данных (клиент) | SQLite (встроенная) | Нулевая конфигурация, надёжность, поддержка WAL для конкурентного доступа |
| База данных (сервер) | SQLite (до 50 сотрудников) / PostgreSQL (более 50) | Гибкость развёртывания |
| Сбор данных (клавиатура/мышь) | `pynput` | Кроссплатформенность; требует учёта ограничений (см. раздел 3.2.5) |
| Получение активного окна | `pygetwindow` + `psutil` + `win32gui` (Windows); `python-xlib` (Linux) | Комбинация библиотек для получения как заголовка, так и имени процесса |
| Автозапуск | Реестр Windows / `.desktop`-файл Linux | Нативный механизм ОС |
| Экспорт PDF | `reportlab` | Зрелая библиотека с поддержкой кириллицы |
| Экспорт XLS | `openpyxl` | Поддержка форматирования и формул |
| HTTP-клиент | `httpx` (async) | Асинхронность, поддержка HTTP/2, таймаутов, повторных попыток |
| Логирование | `loguru` | Структурированные логи, простота настройки |
| Повторные попытки | `tenacity` | Экспоненциальная задержка с джиттером для синхронизации |
| Сборка дистрибутива | PyInstaller | Требование ТЗ; требует мер по снижению ложных срабатываний антивирусов |
| Аутентификация | JWT (access + refresh tokens) | Стандарт де-факто для REST API |
| Планировщик задач | APScheduler | Периодические задачи на сервере (резервное копирование, очистка) |
| Валидация данных | Pydantic v2 | Автоматическая валидация входных данных API |
