Что важно понять на будущее
1. Никогда не применяй --autogenerate без просмотра
Правило: перед alembic upgrade head всегда открывай файл миграции глазами. Ищи:
op.drop_table( — что-то удаляется
op.drop_column( — колонка удаляется
op.drop_index( — индекс удаляется
Если видишь в миграции что-то, чего ты не планировал — не применяй, разбирайся.
2. include_object — теперь наша страховка
После Скрипта 2 при следующей alembic revision --autogenerate партиции records_* больше не будут попадать в миграцию. Проверим это при следующем патче моделей.
3. Если что-то пошло не так
Откатить только последнюю миграцию (не трогая данные):
powershell
docker compose exec api alembic -c /app/server/alembic.ini downgrade -1
Откатить схему полностью (снести всё):
powershell
docker compose down -v
docker compose up -d --build
Тогда Alembic создаст всё с нуля. Но это уже с потерей данных.

Это Alembic --autogenerate увидел партиции в БД (которые PostgreSQL показывает как обычные таблицы), не нашёл их в Base.metadata (там только родительская records) и решил, что их надо удалить.
