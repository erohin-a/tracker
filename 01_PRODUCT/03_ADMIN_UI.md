## Назначение
Карта страниц веб-интерфейса администратора: что есть, зачем нужно, как связано между собой. Служит навигационным справочником для быстрого поиска нужной страницы и её роутов.

## Содержание

### Доступ
- URL входа: `https://localhost/admin/login`
- Логин: `admin`
- Пароль: `ADMIN_API_KEY` из `D:\tracker\.env`
- Сессия хранится в cookie `tracker_admin`
- Первый запуск: `GET /admin/setup` — если таблица `admin_users` пуста

### Навигация
- Sidebar сгруппирован:
  - **Main**: Дашборд
  - **Справочники**: Сотрудники, Отделы, Графики, Компьютеры
  - **Данные**: Отчёты, Сводная, Сессии, Календарь, Аудит
  - **Администрирование**: Токены, Планировщик, Пользователи, Входы, Корзина, Настройки
- Видимость пунктов зависит от роли (`admin_role` в шаблоне).
- Переключатель языка RU/EN в шапке (`/admin/set-lang/{code}`).
- Ссылка на «Мой профиль» — рядом с «Выход».

### Ключевые сценарии
**Первичная настройка:**
1. Вход под `admin`.
2. Создать отделы (`/admin/departments`).
3. Создать сотрудников (`/admin/employees`), указать 1C ID.
4. Проверить календарь (`/admin/calendar`).
5. Настроить параметры (`/admin/settings`).
6. Выпустить bootstrap-токены (`/admin/tokens`) — по одному на ПК.

**Выдача нового ПК:**
1. Выпустить токен.
2. Скопировать, отдать сотруднику.
3. Сотрудник регистрируется в клиенте.
4. Админ привязывает ПК к сотруднику (`/admin/computers`).

**Отчёты:**
1. Форма (`/admin/reports`) — период, отделы, сотрудники, ПК, группировка, формат.
2. HTML-просмотр с раскрытием до сессий и программ.
3. Экспорт CSV/XLSX/PDF.
4. Продвинутый анализ — `/admin/reports/pivot`.

### Внешний вид
- Bootstrap 5.3 через CDN.
- Единый `base.html` — navbar, sidebar, footer.
- Тёмная шапка navbar, светлый контент.
- Туториалы ⓘ рядом с полями (`data-bs-toggle="tooltip"`).
- Хлебные крошки — не используются (навигация через sidebar).

## Ключевые решения
- Все роуты — в одном файле `server/web_admin.py`.
- Шаблоны Jinja2 в `server/templates/`.
- Аутентификация через `SessionMiddleware`, cookie `tracker_admin`.
- 401 → редирект на `/admin/login` (в текущей реализации — нет; в плане).
- i18n через `_()` (Jinja global) + `web_i18n.py`.
- Все страницы используют `{% extends "base.html" %}`.
- Действия администратора пишутся в `audit_log`.
