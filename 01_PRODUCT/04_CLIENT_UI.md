# Клиентский интерфейс (Client UI)
Статус: черновик
Дата: 2026-10-02
Связанные файлы KB: 04_CLIENT\01_ARCHITECTURE.md, 04_CLIENT\06_SETTINGS_UI.md, 01_PRODUCT\02_USER_ROLES.md

## Назначение
Описать интерфейс клиента Tracker: что видит сотрудник на своём ПК, какие действия доступны, как выглядит рабочее окно и трей. Служит навигационным справочником для доработок клиента.

## Содержание

### Точка входа
- Запуск: `python -m client.main` из папки `D:\tracker`.
- При первом запуске — диалог регистрации (`RegistrationDialog`).
- После регистрации — главное окно + иконка в трее.

### Главное окно
**Размер:** ~500×280 px.
**Компоненты сверху вниз:**

| Элемент | Назначение |
|---|---|
| `self.status` | Строка состояния: «Готов к работе», «Работа начата», «Синхронизировано N» и т. д. |
| Кнопка «▶ Начать работу» | Зелёная. Стартует сессию и CollectorWorker |
| Кнопка «■ Конец работы» | Красная. Останавливает сессию и отправляет данные |
| `self.btn_pause` | Кнопка «⏸ Пауза» / «▶ Продолжить» (переключается по состоянию) |
| Панель информации (`QFrame#infoPanel`) | Сессия, счётчик, статус сервера, очередь, последняя синхронизация |
| Чекбокс «Автозапуск при входе в систему» | Вкл/выкл автозапуск |
| Кнопка «⚙ Настройки» | Открывает `SettingsDialog` |

### Панель информации (QFrame)
4 строки в QGridLayout:

| Строка | Левая часть | Правая часть |
|---|---|---|
| 1 | «Сессия» — время старта (локальное) | «Сейчас работаем» — счётчик `HH:MM:SS` |
| 2 | «Сервер» — «✓ онлайн» / «⚠ офлайн» | «Последняя синхронизация» — `DD.MM HH:MM:SS` |
| 3 | «Записей в очереди» — число не отправленных записей | — |

Значения обновляются каждую секунду (`QTimer` → `_update_panel`).

### Системный трей
Иконка в трее — цветной круг с «T»:
| Цвет | Состояние |
|---|---|
| Зелёный | Сессия активна |
| Жёлтый | Пауза |
| Серый | Нет сессии |
| Красный | Офлайн (нет связи с сервером) |

**Контекстное меню трея:**
- «Показать» — разворачивает окно.
- «Начать работу»
- «Конец работы»
- «Выход» — полное завершение приложения.

Закрытие окна (крестиком) не завершает приложение — сворачивает в трей.

### Диалог настроек (SettingsDialog)
Три вкладки (см. `04_CLIENT\06_SETTINGS_UI.md`):
1. **Напоминание** — 6 полей + кнопка «Сбросить к общим».
2. **Общие** — тема, язык, автозапуск, уведомления.
3. **Регистрация** — UID, hostname, URL сервера, отпечаток, bootstrap-токен, перерегистрация.

### Диалог регистрации (RegistrationDialog)
- Показывается, если ПК не зарегистрирован.
- Поле ввода bootstrap-токена + кнопка «Зарегистрировать».
- Статус-ошибки в диалоге (не в трее).
- При успехе — сохраняет `computer_uid` и `client_secret` в keyring.

### Диалог восстановления после краха (UnclosedSessionDialog)
- Показывается при старте, если осталась незакрытая сессия.
- Три варианта:
  1. **Продолжить** — продлить старую сессию.
  2. **Завершить по последней активности** (рекомендуется) — `session_end = last_activity`.
  3. **Завершить сейчас** — `session_end = now`.

### Уведомления
- **Тост трея** — «Свёрнуто в трей», «Связь с сервером потеряна», «Связь восстановлена».
- **Напоминание о старте** — всплывающее окошко, если есть активность без сессии.
- **Напоминание о конце дня** — в заданный час, если сессия ещё идёт.
- **Уведомление об обновлении** — «Доступно обновление X.Y.Z» (обсуждали, в планах).

### Что сотрудник НЕ видит
- Содержимое нажатий (не пишется в принципе).
- Что именно собирается о его активности (в плане — окно «Что собрано за день»).
- Нагрузку на сервер, состояние БД.

## Ключевые решения
- Один диалог настроек, три вкладки.
- Трей — основной интерфейс после старта, окно — вспомогательное.
- Регистрация — только через диалог с bootstrap-токеном, без консоли.
- Состояние кнопок меняется в зависимости от сессии: idle → start, active → stop, paused → resume.
- При завершении приложения с активной сессией — `session_end = last_activity` (не `now`).
- Retranslate главного окна — в планах (сейчас переключение языка требует перезапуска).
