## Назначение
Описать систему напоминаний клиента «Трекер» зачем они нужны, как устроены, когда срабатывают, как настраиваются. Это карта для администратора (что увидит сотрудник) и для разработчика (как доработать).

## Содержание

### Зачем нужны напоминания
- Напоминание о старте сотрудник начал работать за ПК, но забыл нажать «Начать работу». Клиент замечает активность и напоминает.
- Уведомление о конце дня (EOD) сотрудник работает, но забыл нажать «Конец работы». Клиент напоминает в заданный час.

Цель не пропустить рабочее время, не оставить «висящую» сессию.

### Компоненты

 Компонент  Файл  Назначение 
---------
 `ReminderService`  `clientreminder.py`  Логика напоминаний, опрос client-config 
 `reminder_settings`  `clientreminder_settings.py`  Локальные настройки напоминаний в SQLite meta 
 `ActivityWatcher`  `clientactivity_watcher.py`  Пассивный слушатель активности (всегда) 

### Как работает `ReminderService`

Циклы
1. Опрос `client-config` — каждые 5 минут. Получает эффективные настройки (глобальные + персональные).
2. Проверка активности — раз в минуту. Если есть активность без сессии — напоминание.
3. EOD-проверка — раз в минуту. Если сессия идёт и наступило время — напоминание.

Состояние в `meta` SQLite
 Ключ  Что хранит 
------
 `reminder.count_today`  Счётчик напоминаний за сегодня 
 `reminder.last_shown_at`  ISO-время последнего показа 
 `reminder.snooze_until`  ISO-время, до которого отложено 
 `reminder.eod_shown_date`  Дата последнего EOD-напоминания 

### Напоминание о старте

Условия срабатывания
1. `reminder_enabled = True`.
2. Нет активной сессии (`meta.active_session` пусто).
3. Есть активность в течение `reminder_threshold_minutes` (по умолчанию 15 мин).
4. С последнего напоминания прошло ≥ `reminder_repeat_minutes` (по умолчанию 10 мин).
5. Количество напоминаний за день  `reminder_max_per_day` (по умолчанию 5).

Как показывается
- Всплывающее окно с текстом «Похоже, вы работаете. Начать сессию».
- Кнопки «Начать работу»  «Отложить»  «Закрыть».

Действия
- «Начать работу» → вызывает `MainWindow._on_start_work()`.
- «Отложить» → `meta.reminder.snooze_until = now + 10 мин`.
- «Закрыть» → просто закрывает, следующий показ через `reminder_repeat_minutes`.

Счётчик `reminder.count_today++` при каждом показе. Сбрасывается в 0000.

### Уведомление о конце дня (EOD)

Условия срабатывания
1. `end_of_day_hour  0` (0 = выключено).
2. Сессия активна (`meta.active_session` не пусто).
3. Текущее время ≥ `end_of_day_hourend_of_day_minute`.
4. EOD ещё не показывался сегодня (`meta.reminder.eod_shown_date != today`).

Как показывается
- Всплывающее окно с текстом «Рабочий день подходит к концу. Завершить сессию».
- Кнопки «Конец работы»  «Продолжить работу».

Действия
- «Конец работы» → вызывает `MainWindow._on_stop_work()`.
- «Продолжить» → закрывает окно, больше сегодня не показывается.

Счётчик `meta.reminder.eod_shown_date = today` — один раз в день.

### Настройки напоминаний

Глобальные (`app_settings`, `adminsettings`)
 Ключ  По умолчанию  Что значит 
---------
 `reminder_enabled`  `True`  Включить напоминания о старте 
 `reminder_threshold_minutes`  `15`  Минут активности без сессии до первого напоминания 
 `reminder_repeat_minutes`  `10`  Через сколько минут повторять 
 `reminder_max_per_day`  `5`  Максимум напоминаний за день 
 `end_of_day_hour`  `19`  Час EOD-напоминания (0 = выключено) 
 `end_of_day_minute`  `0`  Минуты EOD-напоминания 

Персональные (`employee_settings`, `adminemployees{id}settings`)
- Те же поля, но nullable.
- NULL = «как у всех».
- Не-NULL перекрывает глобальное.

Локальные (`reminder_settings.py`, SQLite meta)
- Копия эффективных настроек на клиенте.
- Обновляется раз в 5 минут из `client-config`.
- Используется, если сервер недоступен.

### Локальные настройки (`reminder_settings.py`)

Функции
- `get_all()` — читает все настройки из `meta`.
- `set_many(dict)` — записывает.

Ключи в `meta`
- `reminder_enabled`
- `reminder_threshold_minutes`
- `reminder_repeat_minutes`
- `reminder_max_per_day`
- `end_of_day_hour`
- `end_of_day_minute`

Источник `client-config` с сервера. Если сервер недоступен — используются последние сохранённые.

### `ActivityWatcher`

Назначение пассивный слушатель активности — фиксирует факт, что пользователь что-то делает.

Отличие от `CollectorWorker`
- Работает всегда (не только при сессии).
- Не пишет records — только устанавливает `meta.last_activity`.
- Используется `ReminderService` для проверки «есть активность, но нет сессии».

Реализация
- `pynput` listeners (keyboard, mouse) — только для обновления `meta.last_activity`.
- Не считает keysclicksscroll.
- При активности — `touch_activity()`.

### Сценарии

#### Сценарий 1 Сотрудник забыл начать сессию
1. Сотрудник включает ПК, начинает работать.
2. Клиент запущен, но сессия не начата.
3. `ActivityWatcher` фиксирует активность → `meta.last_activity` обновляется.
4. Через 15 минут `ReminderService` видит активность есть, сессии нет → показывает напоминание.
5. Сотрудник нажимает «Начать работу» → сессия стартует, счётчик сбрасывается.

#### Сценарий 2 Сотрудник забыл закончить сессию
1. Сотрудник работает, сессия активна.
2. Наступает 1900 (`end_of_day_hour`).
3. `ReminderService` видит сессия идёт, время пришло → показывает EOD.
4. Сотрудник нажимает «Конец работы» → сессия закрывается.
5. Если проигнорировал — напоминание больше не показывается сегодня.

#### Сценарий 3 Напоминание проигнорировано
1. Показано первое напоминание (15 мин).
2. Сотрудник нажал «Закрыть».
3. Через 10 минут (`reminder_repeat_minutes`) — следующее напоминание.
4. И так до `reminder_max_per_day` (5 раз).

#### Сценарий 4 Сотрудник нажал «Отложить»
1. Напоминание показано.
2. Нажал «Отложить» → `meta.reminder.snooze_until = now + 10 мин`.
3. Следующее напоминание не раньше этого времени.

### Взаимодействие с сервером

`GET apiv1client-config` — раз в 5 минут
```json
{
  reminder_enabled true,
  reminder_threshold_minutes 15,
  reminder_repeat_minutes 10,
  reminder_max_per_day 5,
  end_of_day_hour 19,
  end_of_day_minute 0,
  source_reminder global,
  source_end_of_day global
}
source_ показывает, откуда взято значение

global — из app_settings.

personal — из employee_settings.

Если сервер недоступен используются последние сохранённые значения в meta.

Ключевые решения
Два типа напоминаний старт и EOD. Достаточно для целевой аудитории.

Мерж глобальных и персональных настроек. NULL = «как у всех».

ActivityWatcher без records — пассивный, для напоминаний.

Опрос client-config раз в 5 минут — быстрое применение изменений.

Локальные настройки в meta — работают офлайн.

Счётчик напоминаний за день — защита от спама.

Snooze на 10 минут — не отвлекает каждую минуту.

EOD один раз в день — не досаждает.

source_ в client-config — прозрачность видно, откуда значение.
