# Сбор активности
Статус: черновик
Дата: 2026-10-02
Связанные файлы KB: 04_CLIENT\01_ARCHITECTURE.md, 02_METRICS\01_METRICS.md, 04_CLIENT\04_LOCAL_DB.md

## Назначение
Описать, как клиент собирает активность: клавиатуру, мышь, активное окно, idle. Что именно пишется, когда, в каком формате. Это эталон для разработчика, который дорабатывает сбор, и для администратора, который объясняет сотрудникам, что собирается, а что нет.

## Содержание

### Что собирается (и что НЕ собирается)

**Собирается:**
- **Счётчик нажатий клавиатуры** — количество нажатий за интервал (без содержимого).
- **Счётчик кликов мыши** — количество кликов.
- **Счётчик скролла мыши** — количество скроллов.
- **Активное окно** — имя приложения (`app`) и заголовок (`title`) при смене.
- **Idle** — переход в бездействие и возврат из него.

**НЕ собирается:**
- Содержимое нажатий (`COLLECT_KEYSTROKE_CHARS = False`).
- Скриншоты экрана.
- Пароли, тексты, URL.
- Полные заголовки окон (только при смене активного окна).
- Позиция курсора.

### Два слушателя

#### `CollectorWorker` — основной сбор
- Работает **только при активной сессии** (пользователь нажал «Начать работу»).
- Пишет записи в локальную SQLite: `activity`, `window`, `idle`, `idle_end`.
- Останавливается при нажатии «Пауза» или «Конец работы».

#### `ActivityWatcher` — пассивный слушатель
- Работает **всегда**, даже без сессии.
- Фиксирует только факт наличия активности (были ли нажатия/клики).
- **Не пишет records** — используется для напоминаний (`ReminderService`).
- Не влияет на отчёты.

### Коллектор: как работает

#### Класс `CollectorWorker(QObject)`
- Наследник `QObject` (PyQt6) — живёт в отдельном потоке.
- Использует `pynput` для клавиатуры и мыши.
- Опрашивает активное окно каждые `ACTIVE_WINDOW_INTERVAL` (по умолчанию 5 сек).
- Счётчики под `threading.Lock`.

#### Клавиатура
- `pynput.keyboard.Listener` — `on_press`.
- Инкремент `self.key_count` при каждом нажатии.
- **Содержимое нажатия не сохраняется** — только счётчик.
- `COLLECT_KEYSTROKE_CHARS = False` — гарантия.

#### Мышь
- `pynput.mouse.Listener` — `on_click`, `on_scroll`.
- `self.click_count` — количество кликов.
- `self.scroll_count` — количество скроллов.
- Позиция курсора не сохраняется.

#### Активное окно
- Опрос каждые 5 секунд (`ACTIVE_WINDOW_INTERVAL`).
- Получение активного окна через WinAPI (`GetForegroundWindow`, `GetWindowText`) на Windows.
- **Edge-triggered:** запись `window` пишется **только при смене** `(app, title)`.
- Если пользователь работает в одном окне 3 часа — запись одна, в начале.

**Как определяется `app`:**
- Из заголовка окна или через `psutil` по PID.
- Пример: `PyCharm`, `Chrome`, `Excel`, `1С:Предприятие`.

#### Idle
- Порог бездействия: `IDLE_THRESHOLD` (по умолчанию 60 сек).
- Бездействие = нет нажатий клавиатуры и кликов/скролла мыши.
- **Переход в idle:** пишется запись `kind = "idle"` один раз.
- **Возврат из idle:** пишется запись `kind = "idle_end"` один раз.
- Не спамит — только переходы.

### Формат записей в локальной SQLite

#### `kind = "activity"`
Пишется раз в 5 секунд, если за интервал была активность (keys > 0 или clicks + scroll > 0).

```json
{
  "record_uid": "uuid-v4",
  "session_uid": "uuid-v4",
  "kind": "activity",
  "data": {"keys": 5, "clicks": 3, "scroll": 1},
  "client_ts": "2026-10-02T09:05:00+00:00",
  "signature": "hmac-sha256-hex"
}
Логика:

Коллектор накапливает счётчики за 5 секунд.

Если хотя бы один счётчик > 0 — пишется запись.

Если все нули — запись не пишется (нет активности = нет события).

kind = "window"
Пишется только при смене (app, title).

json
{
  "record_uid": "uuid-v4",
  "session_uid": "uuid-v4",
  "kind": "window",
  "data": {"app": "PyCharm", "title": "main.py - Tracker"},
  "client_ts": "2026-10-02T09:15:00+00:00",
  "signature": "hmac-sha256-hex"
}
kind = "idle"
Пишется один раз при переходе через порог бездействия.

json
{
  "record_uid": "uuid-v4",
  "session_uid": "uuid-v4",
  "kind": "idle",
  "data": {"threshold_seconds": 60},
  "client_ts": "2026-10-02T09:30:00+00:00",
  "signature": "hmac-sha256-hex"
}
kind = "idle_end"
Пишется один раз при возврате к активности.

json
{
  "record_uid": "uuid-v4",
  "session_uid": "uuid-v4",
  "kind": "idle_end",
  "data": {"idle_seconds": 120},
  "client_ts": "2026-10-02T09:32:00+00:00",
  "signature": "hmac-sha256-hex"
}
Как записи превращаются в метрики
Окно (window):

В _analyze_session на сервере окно открывается при window-событии.

Закрывается по:

следующему window;

событию idle;

разрыву > activity_gap_minutes (5 мин);

концу сессии.

Сумма всех интервалов окон = Эффективно.

Activity:

Каждое activity-событие с keys > 0 или clicks + scroll > 0 = 5 секунд интенсивной работы.

Сумма × 5 сек = Интенсивная.

Клавиатура/мышь привязываются к текущему активному окну.

Idle:

Закрывает текущее окно.

Не считается эффективным временем.

Учитывается в разрывах.

Настройки, влияющие на сбор
Настройка	Где	По умолчанию	Что делает
ACTIVE_WINDOW_INTERVAL	client/config.py	5 сек	Период опроса активного окна
IDLE_THRESHOLD	client/config.py	60 сек	Порог бездействия для idle
IDLE_CLOSE_MINUTES	client/config.py + сервер	30 мин	Порог авто-закрытия сессии
COLLECT_KEYSTROKE_CHARS	client/config.py	False	Запрет на содержимое нажатий
activity_gap_minutes	/admin/settings	5 мин	Порог разрыва (влияет на расчёт, не на сбор)
Серверные настройки приходят через GET /api/v1/client-config и обновляются раз в 5 минут.

Производительность
CPU: низкая — pynput-листенеры событийные, не polling.

Память: ~20–40 МБ в работе.

Диск: ~30–50 МБ в день на активного сотрудника (батчи в SQLite).

Сеть: ~100–500 КБ в день (батчи раз в 30 сек).

Приватность
Что видит сотрудник:

Он знает, что клиент собирает счётчики.

Он не видит содержимое того, что собирается (не перехватывает свой ввод).

Что видит администратор:

Счётчики (keys, clicks, scroll).

Имя активного приложения и заголовок окна при смене.

Периоды бездействия.

Что НЕ видит никто:

Содержимое нажатий.

Скриншоты.

Содержимое документов/переписки.

Юридически: сбор счётчиков + имени приложения — это мониторинг, требующий согласия сотрудника (152-ФЗ). Скриншоты и содержимое — не собираются, что снижает юридические риски.

Известные проблемы и решения
Проблема	Причина	Решение
Счётчики не растут	pynput не получил доступ к вводу (антивирус, права)	Запуск от имени пользователя, не от admin
Окно не пишется	Заголовок окна не меняется	Edge-triggered — это нормально
Idle не срабатывает	Порог слишком большой	Уменьшить IDLE_THRESHOLD
Спам window при смене	Сравнение (app, title) без нормализации	Нормализовать заголовок
activity пишется, когда нет окна	Окно ещё не сменилось, но активность есть	Норма: привязка к предыдущему окну
Коллектор не останавливается	Поток не завершён	Проверить _stop(), join()
Как добавить новый тип сбора
Добавить kind (например, "focus") в _analyze_session на сервере.

Добавить логику в CollectorWorker.

Добавить обработку в db.insert_record.

Обновить схему data (JSON).

Обновить метрики в 02_METRICS\01_METRICS.md.

Ключевые решения
Счётчики, не содержимое. Приватность + 152-ФЗ.

Edge-triggered window. Не спамит, экономит место.

Idle только по переходам. Одна запись на вход, одна на выход.

Activity раз в 5 сек. Компромисс между точностью и объёмом.

Коллектор только при сессии. Без сессии — не пишет.

ActivityWatcher всегда. Для напоминаний, без записей.

Счётчики под Lock. Потокобезопасность.

pynput. Кроссплатформенный, событийный.

COLLECT_KEYSTROKE_CHARS = False. Жёсткая гарантия приватности.
