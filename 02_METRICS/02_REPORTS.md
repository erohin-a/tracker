# Отчёты
Статус: черновик
Дата: 2026-10-02

## Назначение
Описать механику формирования, отображения и экспорта отчётов в веб-админке. Это карта для администратора, который строит отчёт, и для разработчика, который его дорабатывает.

## Содержание

### Форма отчёта (`/admin/reports`)
Основной интерфейс для настройки отчёта. Состоит из нескольких блоков.

#### 1. Период
- **Поля:** `date_from` (date), `date_to` (date).
- **Кнопки быстрых периодов:** «Сегодня», «Вчера», «7 дней», «30 дней», «Этот месяц», «Прошлый месяц», «Этот год».
- **Кнопка сброса:** «Сбросить фильтры» — очищает все поля и удаляет сохранённые настройки из `localStorage`.

#### 2. Фильтры
- **Отделы:** `department_ids` (multiple select с поиском).
- **Сотрудники:** `employee_ids` (multiple select с поиском).
- **Компьютеры:** `computer_ids` (multiple select с поиском).
- **Зависимая фильтрация:** при выборе отдела список сотрудников и ПК фильтруется по этому отделу (JS-логика на `emp_dept_map`).

#### 3. Параметры отчёта
- **Группировка (`group_by`):**
  - `days` — «Рабочие дни × Сотрудник» (табель).
  - `months` — «Месяц × Сотрудник».
  - `employees` — «По сотрудникам».
  - `departments` — «По отделам».
  - `computers` — «По компьютерам».
  - `sessions` — «Детально — каждая сессия».
- **Формат (`fmt`):** `html` (просмотр), `xlsx`, `csv`, `pdf`.
- **Чекбоксы:**
  - `show_apps` — показывать блок «Топ программ».
  - `show_abnormal` — помечать аварийные сессии (⚠).
  - `expand_details` — разворачивать детали строк по умолчанию.

#### 4. Сохранение фильтров
- Все значения формы сохраняются в `localStorage` под ключом `tracker_report_filters_v1`.
- При открытии страницы фильтры восстанавливаются.
- Кнопка «Сбросить фильтры» очищает `localStorage` и сбрасывает форму.

### HTML-вид результата (`report_result.html`)
После отправки формы (POST `/admin/reports/generate`) открывается страница с результатом.

#### 1. Строка контекста
- Период (`date_from` — `date_to`).
- Часовой пояс (`report.tz_name`).
- Начало рабочего дня (`report.workday_start_hour`).
- Группировка.
- Всего сессий.
- Количество сотрудников и отделов.
- Количество аварийных сессий (⚠).

#### 2. Плашка «ИТОГО по фильтру»
Пять ключевых метрик (см. `02_METRICS\01_METRICS.md`):
- Отработано (span).
- С трекером (union).
- Интенсивная.
- Эффективно.
- Пауза.

#### 3. Блок «Топ программ» (если `show_apps`)
- Таблица: Программа | Время | Клавиатура | Мышь.
- Раскрытие (`details`) — список сотрудников, работавших в этой программе (`a.by_employee`).

#### 4. Основная таблица
Колонки зависят от группировки.

| Группировка | Колонки |
|---|---|
| `days` | Рабочий день, Сотрудник, 1C ID, Отдел, Сессий, Отработано, С трекером, Интенсивная, Эффективно, Пауза, ⚠ |
| `months` | Месяц, Сотрудник, 1C ID, Отдел, Дней, Сессий, метрики |
| `employees` | Сотрудник, 1C ID, Отдел, Дней, Сессий, метрики |
| `departments` | Отдел, Сотрудников, Дней, метрики |
| `computers` | Компьютер, Дней, Сессий, метрики |
| `sessions` | Рабочий день, Сотрудник, 1C ID, Компьютер, Начало, Конец, метрики |

**Подсветка:**
- `r.day_type == 'weekend'` → `table-warning` + badge «вых».
- `r.day_type == 'holiday'` → `table-danger` + badge «празд.».
- ФИО «--- не привязан ---» → серым курсивом (`text-muted fst-italic`).

**Раскрытие строки (details):**
- Сессии: Начало, Конец, Отработано, Интенсивная, Эффективно, Пауза, Авар.
- Программы: Программа, Время, Клавиатура, Мышь.

#### 5. Кнопка PDF
- Форма `POST /admin/reports/generate` с `fmt=pdf` и всеми текущими фильтрами.

### Блок «Без привязки»
Отображается внизу HTML-отчёта, если есть сессии без `employee_id`.

- **Назначение:** показать ПК, которые работали, но не привязаны к сотруднику. Их данные не попадают в отчёты по сотрудникам/отделам.
- **Содержимое:**
  - Hostname, UID, количество сессий, суммарный span, первая и последняя дата.
- **Действия:**
  - Форма привязки: `POST /admin/computers/{id}/assign-unattached` — привязывает все непривязанные сессии этого ПК к выбранному сотруднику.
  - Форма удаления: `POST /admin/computers/{id}/delete-unattached` — удаляет все непривязанные сессии этого ПК за период отчёта.

### Права и роли
- **admin, operator, hr, viewer:** видят отчёты.
- **manager:** видит отчёты только по своему отделу. Фильтры по отделам, сотрудникам и ПК принудительно ограничиваются его `department_id`.
- **viewer:** только просмотр, экспорт доступен.

### Форматы экспорта
- **HTML:** просмотр в браузере (описан выше).
- **CSV:** 15 колонок. Разделитель `;`. Кодировка UTF-8 с BOM. Строка ИТОГО в конце.
- **XLSX:** два листа — «Данные» (15 колонок, автофильтр, `[HH]:MM:SS` для длительностей, `DD.MM.YYYY` для даты) и «ИТОГО» (сводка).
- **PDF:** в текущей реализации — старые колонки, требует обновления (P0).

### Ограничения и лимиты
- HTML-отчёт показывает до 500 строк (если больше — предупреждение «показаны не все»).
- XLSX/CSV — без лимита, но при больших объёмах растёт время генерации.
- PDF — landscape A4, шрифт DejaVuSans, требует наличия файла `server/fonts/DejaVuSans.ttf`.

## Ключевые решения
- Шесть группировок покрывают все типовые сценарии: табель, сводка по месяцам, по сотрудникам, отделам, ПК и детализация.
- Все фильтры сохраняются в `localStorage` — администратор не теряет настройки при перезагрузке.
- Блок «Без привязки» решает проблему «потерянных» сессий: их можно привязать или удалить, не выходя из отчёта.
- Подсветка выходных/праздников берётся из календаря (`calendar_days`).
- Формат времени — всегда `HH:MM:SS`, независимо от длительности.
- XLSX готов к построению сводной таблицы: одна строка = один день одного сотрудника, без ИТОГО на листе «Данные».
- Pivot-таблица — отдельная страница (`/admin/reports/pivot`), не часть формы отчёта.
