# Метрики отчётов
Статус: черновик
Дата: 2026-10-02
Связанные файлы KB: 01_PRODUCT\06_GLOSSARY.md, 02_METRICS\02_REPORTS.md, 03_SERVER\10_SETTINGS.md

## Назначение
Определить пять ключевых метрик отчётов, их формулы, примеры и краевые случаи. Это эталон для реализации, проверки и объяснения заказчику.

## Содержание

### Пять ключевых метрик
Все метрики вычисляются за период (день, месяц, произвольный диапазон) и по группе (сотрудник, отдел, ПК).

| # | Метрика | Формула | Смысл |
|---|---|---|---|
| 1 | **Отработано** (span) | `max(end_local) − min(start_local)` по всем сессиям группы за день | табель: от прихода до ухода |
| 2 | **С трекером** (union) | длина объединения интервалов `[activity_start, activity_end]` всех сессий группы за день | сумма без двойного счёта при работе на 2 ПК |
| 3 | **Интенсивная** | `5 сек × count(activity-события с keys>0 ИЛИ clicks+scroll>0)` | реально стучал по клавишам и мыши |
| 4 | **Эффективно** | сумма интервалов активных окон, обрезанных по `activity_gap_minutes` (5 мин) и по idle | был в приложении |
| 5 | **Пауза** | `Σ pause_seconds` (кнопка) + (Отработано − С трекером) | всё неэффективное время |

### Дополнительные поля
| Поле | Формула | Назначение |
|---|---|---|
| **Сессий** | `count(work_sessions)` в группе | сколько раз сотрудник запускал сессию |
| **Дней** | `count(distinct workday_date)` в группе | сколько уникальных дней было активных |
| **Аварийных** | `count(abnormal_termination = True)` | сколько сессий закрыто не пользователем |
| **Компьютеров** | `count(distinct computer_id)` | сколько ПК использовал сотрудник |
| **Клавиатура** (по приложению) | `5 сек × count(activity с keys>0 в этом окне)` | для разбивки по программам |
| **Мышь** (по приложению) | `5 сек × count(activity с clicks+scroll>0 в этом окне)` | для разбивки по программам |

### Определения (важные)

**Окно (window)**
- Клиент пишет `window` при смене активного приложения.
- В `_analyze_session` окно закрывается в момент:
  - следующего `window`-события;
  - события `idle`;
  - разрыва между любыми событиями > `activity_gap_minutes`;
  - конца сессии.
- Сумма всех интервалов окон = **Эффективно**.

**Активность (activity)**
- Клиент пишет `activity` раз в 5 секунд, если за интервал был хотя бы один key/click/scroll.
- Каждое событие = 5 секунд интенсивной работы.
- Ключ/мышь привязываются к текущему активному окну.

**Idle**
- Клиент пишет `idle` при переходе через порог 60 сек без активности.
- `idle_end` — при возврате к работе.
- Idle немедленно закрывает текущее окно и не считается эффективным временем.

**Пауза (кнопка)**
- Пользователь нажимает «⏸ Пауза» на клиенте.
- На это время клиент останавливает `CollectorWorker`, records не пишутся.
- `pause_seconds` накапливается в сессии.
- В отчёте: `Пауза = Σ pause_seconds + (Отработано − С трекером)`.

**Перерывы между сессиями**
- Разница `Отработано − С трекером` = сумма промежутков между сессиями одного сотрудника за день.
- Включаются в «Паузу».

**Параллельная работа на 2 ПК**
- Один сотрудник запустил сессии на двух ПК одновременно.
- «Отработано» = span одного дня (учитывая обе сессии).
- «С трекером» = union интервалов (без двойного счёта).
- «Эффективно» = сумма активных окон с учётом перекрытий.

### Краевые случаи
1. **Сессия через полночь.** Если сессия началась в 22:00 и закончилась в 06:00, при `workday_start_hour=6` она относится к предыдущему рабочему дню целиком. Не разделяется.
2. **Пустая сессия (нет events).** `effective = 0`, `intensive = 0`, `full_duration = end − start`. Учитывается в Отработано, но не в Эффективно.
3. **Длинная сессия с одним окном.** Если окно открыто 9 часов, но пользователь не пишет activity — окно закрывается на последнем событии, а не на `end_local`.
4. **Пользователь свернул окно, но оставил ПК.** Клиент не пишет window, потому что приложение активно. Окно продолжает считаться активным. Idle закрывает окно.
5. **Две сессии, пересекающиеся по времени на 2 ПК.** Span считается от `min(start) до max(end)`; union их объединяет; Пауза = Σ pause + (span − union).
6. **Пропущенный `idle_end` из-за падения клиента.** После восстановления сессия закрывается по `last_activity` (а не `now`), и окна корректно обрезаются.
7. **Нет ни одной activity-записи в сессии.** `effective = 0`, `intensive = 0`, но `full_duration > 0`. В отчёте сессия видна, но время работы = 0.
8. **Отрицательная пауза из-за бага старых данных.** В коде применяется `max(0, ...)` — Пауза не может быть отрицательной.

### Пример расчёта (согласован с заказчиком)
Исходные данные за день для одного сотрудника:
- Сессия 1: 08:00–12:00 (4:00).
- Перерыв: 12:00–13:00 (1:00) — трекер выключен.
- Сессия 2: 13:00–17:00 (4:00), внутри кнопка «Пауза» с 13:30 до 14:30 (1:00).

Результат:
| Метрика | Значение |
|---|---|
| Отработано | 9:00 |
| С трекером | 8:00 |
| Эффективно | 7:00 (4:00 в 1-й + 3:00 во 2-й) |
| Интенсивная | зависит от реальной активности, например 4:30 |
| Пауза | 2:00 = 1:00 (перерыв) + 1:00 (кнопка) |

Проверка: `Отработано − Пауза = 9:00 − 2:00 = 7:00 = Эффективно`. Сходится.

### Что НЕ считается
- Содержимое нажатий (не пишется).
- Скриншоты экрана (не пишутся).
- Время, когда клиент был выключен, но сессия не закрыта — попадает в span, но не в эффективное.
- Время работы приложений, которые активно не были (не open, а idle).

## Ключевые решения
- Пять метрик, независимых друг от друга. Каждая отвечает на свой вопрос.
- «Эффективно» ≠ `session_end − session_start`. Это сумма активных окон.
- «Пауза» = кнопка + перерывы между сессиями (согласовано с заказчиком).
- `Интенсивная ≤ Эффективно ≤ С трекером ≤ Отработано` — важное отношение для валидации.
- Окно закрывается по gap/idle, а не по `end_local` сессии — защита от «открыл 1С и ушёл на 9 часов».
- Метрики кэшируются в `daily_stats` (для ускорения отчётов за прошлые месяцы).
