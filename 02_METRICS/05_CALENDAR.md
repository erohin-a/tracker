# Календарь
Статус: черновик
Дата: 2026-10-02

## Назначение
Описать календарь рабочих/нерабочих дней: зачем он нужен, как заполняется, как влияет на отчёты и какие настройки с ним связаны. Это карта для администратора, который ведёт календарь, и для разработчика, который дорабатывает отчёты.

## Содержание

### Что такое календарь в «Трекере»
- Календарь — это таблица `calendar_days` в PostgreSQL, где для каждой даты указано, является ли она рабочей.
- Заполняется администратором вручную через страницу `/admin/calendar`.
- Используется в отчётах для:
  - определения типа дня (`working` / `weekend` / `holiday`);
  - подсветки выходных и праздников в HTML-отчёте;
  - корректного расчёта метрик (учёт или неучёт выходных — настройка `count_weekends`).

### Модель `CalendarDay`
| Поле | Тип | Описание |
|---|---|---|
| `day` | String(10), PK | ISO-дата `YYYY-MM-DD` |
| `is_working` | Boolean | `True` — рабочий, `False` — нерабочий |
| `note` | String(255) | Примечание (праздник, перенос и т.п.) |
| `updated_at` | DateTime | Когда запись обновлена |

Если записи на дату нет — используется правило по умолчанию: `is_working = (weekday() < 5)`, то есть Пн–Пт рабочие, Сб–Вс нерабочие.

### Страница `/admin/calendar`
**Отображение:**
- Год по месяцам: 12 месяцев, каждый — сетка дней (7 колонок, Пн–Вс).
- Чекбокс на каждом дне: отмечен = рабочий.
- Суббота и воскресенье подсвечены `bg-warning-subtle`.
- Нерабочие дни — зачёркнуты (`text-decoration: line-through`).
- Переключатель года: выпадающий список (`GET /admin/calendar?year=YYYY`).
- Сводка: «Рабочих дней: N из 365».

**Действия:**
- **Сохранить** — `POST /admin/calendar/save` — сохраняет только изменения (сравнение с дефолтом, чтобы не плодить лишние записи).
- **Сгенерировать** — `POST /admin/calendar/generate` — заполняет год по дефолту (Пн–Пт рабочие, Сб–Вс нет), перезаписывая существующие записи.
- **Сбросить** — `POST /admin/calendar/reset` — удаляет все записи за год (возврат к дефолту).

**Права:**
- admin, operator, hr — могут просматривать и редактировать.
- manager, viewer — не имеют доступа к странице.

### Связь с `workday_start_hour`
- `workday_start_hour` (по умолчанию 6) — час, с которого начинается новый рабочий день.
- Сессия, начавшаяся до этого часа, относится к предыдущему рабочему дню.
- Пример: сессия началась в 02:00. При `workday_start_hour = 6` она относится к вчерашнему дню, потому что 2 < 6.
- Функция `_workday_date(start_local, workday_start_hour)` вычисляет дату рабочего дня.

### Влияние на отчёты
1. **Тип дня (`day_type`):**
   - `_day_type(db, d)` возвращает:
     - `working` — рабочий день.
     - `weekend` — суббота/воскресенье, не отмеченное как рабочий.
     - `holiday` — нерабочий день, отличный от выходного (например, 1 мая).
   - Используется в `_build_flat_records` и передаётся в `report_result.html`.

2. **Подсветка в HTML-отчёте:**
   - `day_type == 'weekend'` → `table-warning` + badge «вых».
   - `day_type == 'holiday'` → `table-danger` + badge «празд.».
   - Только для группировки `days`.

3. **Настройка `count_weekends`:**
   - Если `False` — выходные и праздники исключаются из расчёта метрик.
   - Если `True` — учитываются наравне с рабочими днями.
   - Хранится в `app_settings`, редактируется в `/admin/settings`.

### Пример работы
**Дано:** календарь на 2026 год, 9 мая — праздник (нерабочий), 10 мая — суббота.
**Сотрудник работал 9 мая 4 часа.**
- В отчёте строка за 9 мая будет с `day_type = 'holiday'` (подсветка красным).
- Если `count_weekends = False`, эти 4 часа не попадут в общие метрики.
- Если `count_weekends = True`, попадут.

### Роуты
| Метод | Путь | Назначение |
|---|---|---|
| GET | `/admin/calendar` | Страница календаря |
| POST | `/admin/calendar/save` | Сохранить изменения |
| POST | `/admin/calendar/generate` | Сгенерировать год по дефолту |
| POST | `/admin/calendar/reset` | Удалить все записи за год |

### Ключевые функции
- `_get_calendar_map(db, year)` — словарь `{date_iso: is_working}` для года.
- `_is_working_day(db, d)` — рабочая ли дата.
- `_day_type(db, d)` — `working` / `weekend` / `holiday`.
- `_workday_date(start_local, workday_start_hour)` — дата рабочего дня.

## Ключевые решения
- **Календарь годовой.** Заполняется на год вперёд, можно переключать годы.
- **Дефолт — Пн–Пт рабочие.** Не нужно заполнять вручную, если нет праздников.
- **Сохранение только изменений.** `calendar_save` сравнивает с дефолтом, чтобы не создавать лишние записи.
- **Генерация перезаписывает.** `calendar_generate` сбрасывает год к дефолту.
- **Сброс удаляет.** `calendar_reset` удаляет все записи за год.
- **Подсветка в отчётах.** Выходные — жёлтым, праздники — красным.
- **`count_weekends` управляет учётом.** Глобальная настройка, влияет на все отчёты.
