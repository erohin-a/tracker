# Известные проблемы
Статус: черновик
Дата: 2026-10-02
Связанные файлы KB: 07_QUALITY\01_TESTING.md, 07_QUALITY\03_DIAGNOSTICS.md, 09_OPS\01_RUNBOOK.md

## Назначение
Сводка известных проблем «Трекера» с симптомами, причинами и решениями. Это справочник для администратора, который разбирается с инцидентом, и для разработчика, который вносит правки.

## Содержание

### Как пользоваться
- **Симптом** — что видно (ошибка, сообщение, поведение).
- **Причина** — почему это происходит.
- **Решение** — что делать.
- **Статус** — исправлено / в работе / отложено.

### Проблемы регистрации и аутентификации

#### 1. `getaddrinfo failed`
| | |
|---|---|
| **Симптом** | `[Errno 11001] getaddrinfo failed` в `client.log` |
| **Причина** | Python резолвит `localhost` в IPv6 `::1`, Docker Desktop плохо пробрасывает IPv6 |
| **Решение** | В `client/.env` использовать `TRACKER_SERVER_URL=https://127.0.0.1` |
| **Статус** | Исправлено |

#### 2. `SSL: CERTIFICATE_VERIFY_FAILED`
| | |
|---|---|
| **Симптом** | `ssl.SSLCertVerificationError: self-signed certificate in certificate chain` |
| **Причина** | Python не доверяет самоподписанному сертификату |
| **Решение** | Скопировать `fullchain.pem` в `%APPDATA%\Tracker\ca.pem` |
| **Статус** | Исправлено |

#### 3. `Hostname mismatch`
| | |
|---|---|
| **Симптом** | `certificate is not valid for 'localhost'` |
| **Причина** | Сертификат выпущен без SAN-поля |
| **Решение** | Перевыпустить с `-addext "subjectAltName=DNS:localhost,IP:127.0.0.1"` |
| **Статус** | Исправлено |

#### 4. `401 Unauthorized` на регистрации
| | |
|---|---|
| **Симптом** | `{"detail": "Invalid or expired bootstrap token"}` |
| **Причина** | Токен уже использован, истёк, или введён с пробелами |
| **Решение** | Выпустить новый через `/admin/tokens` |
| **Статус** | Работает как задумано |

#### 5. Сгорел bootstrap-токен
| | |
|---|---|
| **Симптом** | `401` при регистрации |
| **Причина** | Токен уже использован, TTL истёк |
| **Решение** | Выпустить новый токен, перерегистрировать |
| **Статус** | Работает как задумано |

#### 6. `.env` читается не тот
| | |
|---|---|
| **Симптом** | Клиент не находит `TRACKER_SERVER_URL` |
| **Причина** | При запуске из `D:\tracker` читается серверный `.env`, а не `client/.env` |
| **Решение** | В `config.py` порядок поиска: сначала `client/.env`, потом `%APPDATA%/Tracker/.env` |
| **Статус** | Исправлено |

#### 7. `.env` в UTF-16 с BOM
| | |
|---|---|
| **Симптом** | Переменные не читаются |
| **Причина** | PowerShell `>` пишет в UTF-16 |
| **Решение** | Использовать `[System.IO.File]::WriteAllText` с `UTF8Encoding($false)` |
| **Статус** | Исправлено |

#### 8. `role "tracker" does not exist`
| | |
|---|---|
| **Симптом** | Ошибка подключения к БД |
| **Причина** | Пользователь не создан |
| **Решение** | Проверить `POSTGRES_USER` в `docker-compose.yml` |
| **Статус** | Работает как задумано |

Middleware для логирования 500:

python
@app.middleware("http")
async def log_500(request, call_next):
    try:
        response = await call_next(request)
    except Exception:
        log.exception("Unhandled error on %s %s", request.method, request.url.path)
        raise
    if response.status_code >= 500:
        log.error("Server error %s on %s %s", response.status_code, request.method, request.url.path)
    return response
